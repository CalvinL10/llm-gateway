# v0.3.0-rc.1 — candidate for DSH 0.2.1-rc.3

[中文](v0.3.0-rc.1.md) | **English**

Adds Codex / ChatGPT, Antigravity and Claude subscription connections to
ordinary DSH conversations, with independent main/default-child models and
per-delegation model choices. Native DeepSeek and other API providers remain
available and may be mixed with subscription providers. Installation does
not sign in or change model defaults.

## Install

Paste this release asset URL into DSH's Add Plugin input:

[llm-gateway-dsh-subscriptions-0.3.0-rc.1.tgz](https://github.com/CalvinL10/llm-gateway/releases/download/v0.3.0-rc.1/llm-gateway-dsh-subscriptions-0.3.0-rc.1.tgz)

Restart when prompted. Open Settings → 订阅连接与模型设置, sign in, refresh
the catalog and save your choices, then create an ordinary conversation.
Use the `.tgz` asset, not the repository homepage or Source code archives.
The default npm registry is sufficient.

Package: `@llm-gateway/dsh-subscriptions` version `0.3.0-rc.1`, targeting host
`0.2.1-rc.3`. It uses native bundle registration, client settings slots, model
registration and configuration editing. Independent child models apply to
native spawn subagents. Fork and external-product agents retain their host
settings. Saved defaults apply to new sessions, not running ones.

## Verified

Environment: Windows, Node 24.15.0, native npm DSH 0.2.1-rc.3, isolated test
Home, loopback and headless Microsoft Edge. The installed desktop app and
desktop-host package also report 0.2.1-rc.3. All 14 tests passed without skips.

- Native plugin manager installation/removal/reinstallation of the built `.tgz`.
- Ordinary sessions, default and explicit child models, mixed provider routing.
- Native API adapter reaching an independent local HTTP server as main and
  child model; API access still works after uninstalling this plugin.
- Restart persistence, preserving main defaults when editing child models,
  and preserving existing permissions, presets and fork configuration.
- Unauthenticated requests return 401; foreign-origin settings writes return
  403. Account settings are served only through protected native routes.
- Controlled protocol tests using the original three adapters, including
  authorization headers and tool-call/result round trips.
- Real browser loading, three login cards, saved main/child model choices,
  ordinary new conversation selection and no client script errors.
- The installed desktop CLI, Electron Node and desktop-host install and boot
  the plugin in an isolated Web test profile; model catalog and all three
  account status routes respond. No desktop window opens. This does not
  cover the actual desktop renderer transport or the daily-use profile.

Tests live in `integrations/dsh-subscriptions/test`. See that package's guide
for runtime and browser-preview setup. Environment-dependent tests report
skips when setup is absent, not passes.

## Remaining acceptance

**Desktop release-URL installation, desktop transport, real account sign-in
and real model calls remain unverified.** No existing user credentials were
read and no live subscription quota was used. This is a candidate release,
not a guarantee of account access, billing behavior or continued service.

The MIT-licensed connection modules come from
`@eddyskywalker/dsh-chatgpt-subscription` 0.42.0 with original authorization,
credential protection and request controls. Only three connections are
composed; upstream global search, tool and delegation-policy extensions are
not mounted. Community access does not establish endorsement by OpenAI,
Google or Anthropic. See the included notices and upstream license.

The legacy v0.2.0 task plugin remains in source. Its task UI has not been
ported to 0.2.1 and is not included in this package.
